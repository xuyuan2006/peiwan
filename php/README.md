# 陪玩点单系统（原生 PHP + MySQL）

一套可直接部署上线的游戏陪玩点单平台：**用户点单 → 陪玩接单 → 服务完成 → 平台抽成分账**，带钱包资金体系（充值 / 提现 / 流水 / 冻结）与完整管理后台。

- 后端：原生 PHP（PDO 预处理，无 Composer 依赖，虚拟主机/宝塔直接跑）
- 数据库：MySQL 5.7+ / 8.0（InnoDB、utf8mb4）
- 前端：服务端渲染 HTML + 原生 CSS/JS（无框架、无构建步骤）
- 路由：`index.php?r=控制器/方法`（不需要 URL 重写，兼容所有主机）

## 快速验收（三步，约 5 分钟）

| 步骤 | 做什么 | 期望结果 |
| --- | --- | --- |
| 1 | 上传代码 → **运行目录指向 `public/`** → 访问 `/install.php` | 环境自检全绿 → 填数据库、**站点名称、管理员账号 + 强密码、自定义后台入口** → 建 20 张表并写入初始游戏与设置 |
| 2 | 用安装时设置的后台入口登录（默认 `/admin/index.php`；改了名字就是 `/你的名字/index.php`），再访问 `/check.php` | 语法、SQL 占位符、路由三项显示 **PASS**；数据库 20 张表齐全；安全项只剩"删除自检文件"类提示 |
| 3 | 同一后台登录状态下访问 `/selftest.php` → 点「开始自检」 | 30+ 条资金链路断言全部「通过」（下单→支付→接单→完成→分账→评价→退款→**后台代客下单（自定义金额/立即支付/余额不足回滚）**→提现→打款/驳回→调账 + 防护类断言），跑完自动清理临时数据 |

可选：访问 `/demo.php` 一键生成演示数据（3 位陪玩、待审核陪玩、2 位买家、4 笔不同状态订单、待确认充值单、待审核提现单），用来逐个体验后台审核流程；同页可一键清除。

### 安装向导的安全设计（针对"默认入口 + 弱密码被爆破"）

- **管理员密码强制强度**：至少 8 位、必须同时包含字母与数字，并挡掉 `123456`／`admin123`／`password` 等常见弱口令（也不允许与账号相同）；向导里可一键「随机生成强密码」并自动复制到剪贴板
- **后台入口可改名**：向导里填 `manage8x` 之类的名字，安装时会自动把 `public/admin` 改名为 `public/manage8x`，并把 `security.admin_path` 写入 `config/config.php`；此后**默认的 `/admin/` 直接返回 404**（`public/admin/index.php` 里有校验，所以以后更新时误传回来的 `admin/` 目录也不会变成绕过入口）
- **改名失败不会把站搞挂**：只有确认 `config` 可写才动目录；目录改名或配置写入失败都会自动回滚到原入口，并在向导结果页用黄条说明原因
- **事后想换入口**：把 `public/旧名字` 改名为 `public/新名字`，再把 `config/config.php` 里 `security.admin_path` 改成同一个名字（**两处必须一致**）
- 安装完请删除或重命名 `install.php`（向导结果页也会提醒）

**上线前务必**：删除 `install.php` / `check.php` / `selftest.php` / `demo.php`，并把 `config/config.php` 的 `app.debug` 保持为 `false`（安装向导默认写入 `false`）。

## 三、部署步骤

### 环境要求
- PHP ≥ 7.4（推荐 8.0/8.1），扩展：`pdo_mysql`、`mbstring`、（上传图片建议）`fileinfo`
- MySQL ≥ 5.7（推荐 8.0）
- Apache / Nginx / IIS 均可

### 方式 A：宝塔面板（推荐）
1. 新建站点 → PHP 选 7.4+ → 创建数据库（记住库名/用户/密码）
2. 上传整个目录到站点根目录，例如 `/www/wwwroot/peiwang`
3. **站点设置 → 网站目录 → 运行目录 改为 `/public`**（必须，否则源码可被下载）
4. 目录权限：`config/` 需可写（安装时写入配置），`public/uploads/` 需可写
5. 浏览器访问 `http://你的域名/install.php`，按向导填写数据库与管理员信息

### 方式 B：虚拟主机
1. 上传全部文件
2. 若无法修改运行目录，可把 `public/` 里的文件移到网站根目录，并同步修改：
   - `public/index.php` 中 `require dirname(__DIR__) . '/app/bootstrap.php'` → 改成 `require __DIR__ . '/../app/bootstrap.php'` 前请保持 app 在网站根目录上一级；
   - 更简单的做法：把 `app/`、`config/`、`sql/`、`cron/` 放在根目录，`public/*` 内容也放到根目录，并把 `public/admin/index.php` 里的 `dirname(__DIR__, 2)` 改为 `dirname(__DIR__)`。
3. 访问 `/install.php` 安装

### Nginx 配置
直接抄 `deploy/nginx.conf.example`（含 HTTPS 版本、上传目录禁执行脚本、后台限制来源 IP 等注释开关）。核心是一句话：**`root` 指向项目的 `public` 目录**。

### 方式 C：本地开发（PHP 内置服务器）
```bash
cd public
php -S 127.0.0.1:8080
# 浏览器打开 http://127.0.0.1:8080/install.php
```

### 装完先跑一次自检（强烈建议）
浏览器访问 `http://你的域名/check.php`，它会做四件事：
1. 用 PHP 内置语法解析器检查全部 PHP 文件（**等价于 `php -l`，不需要命令行权限**）
2. 逐个提取 `Db::one/all/value/query` 的 SQL 与绑定参数，核对 `?` 占位符个数与参数个数是否一致
3. 扫描全项目 `url('控制器/方法')`，核对是否都有对应的控制器方法
4. 检查 PHP 版本/扩展/目录可写、数据库连接与 20 张表结构、列出上线前必须处理的安全项；**与 `sql/schema.sql` 对比后缺表/缺字段会直接告诉你**（升级时到 install.php 会自动补齐）

> 权限：**系统装好后本页只对已登录的管理员显示完整报告**；未安装（或未登录）时只显示语法与环境检查，不会泄露数据库名、表结构与服务器路径。所以请先登录后台再访问。

确认无误后请删除 `public/check.php` 和 `public/install.php`。

### 想先看看有数据的样子？（可选）
管理员登录后台后访问 `http://你的域名/demo.php`，一键生成 3 位陪玩（含技能）、1 位待审核陪玩、2 位有余额的买家、4 笔不同状态的订单、1 笔待确认充值单、1 笔待审核提现单，方便逐个体验后台审核流程。演示账号用户名都以 `demo_` 开头（统一密码 `demo123456`），同页面可一键清除。

### 再跑一次业务自检（验证资金链路）
用管理员登录后台后，浏览器访问 `http://你的域名/selftest.php`。它会自动创建两个临时账号，把
**下单 → 余额支付 → 接单 → 提交完成 → 确认 → 平台抽成分账 → 评价与评分重算 → 取消退款 → 提现申请(冻结) → 后台打款 → 驳回解冻 → 人工调账 → 非法流转拦截**
全流程跑一遍，逐条输出「通过/失败」和实际金额，结束后自动删除自己创建的全部数据。全部显示「通过」就说明资金逻辑正确。

```bash
chmod -R 775 /www/wwwroot/peiwang/config /www/wwwroot/peiwang/public/uploads
chown -R www:www /www/wwwroot/peiwang
```

## 四、安装后的首次测试流程

1. 访问安装向导，创建管理员（例如 `admin` / `admin123456`）
2. 前台注册一个普通用户（买家）和一个陪玩账号（卖家）
3. 陪玩账号登录 → 「成为陪玩」提交入驻资料
4. 管理员登录 `/admin/index.php` → 陪玩管理 → 审核通过
5. 陪玩进入「陪玩中心 → 技能管理」上架服务（选游戏、服务类型、价格）
6. 买家在前台找到该陪玩 → 选服务 → 下单 → 我的订单 → 立即支付
   （余额不足先到「钱包 → 充值」，人工渠道时由管理员在后台「充值审核 → 确认到账」）
7. 陪玩「我的接单 → 立即接单 → 提交完成」
8. 买家「确认完成」→ 系统按抽成比例结算给陪玩（可到钱包流水查看）
9. 买家评价 → 陪玩在订单详情回复
10. 陪玩「钱包 → 提现」→ 管理员后台「提现审核 → 已打款 / 驳回」

| 1 | 待支付 | 下单后未支付，超时自动关闭 | 支付、取消 |
| 2 | 待接单 | 已支付，等待陪玩接单 | 陪玩接单、用户取消（全额退款） |
| 3 | 服务中 | 陪玩已接单 | 陪玩提交完成、用户申请退款 |
| 4 | 待确认 | 陪玩已提交完成 | 用户确认完成（触发结算）、自动确认、申请退款 |
| 5 | 已完成 | 已结算：平台抽成 + 陪玩入账 | 评价 |
| 6 | 退款中 | 用户发起退款，等平台处理 | 后台同意（退款）/ 驳回（回到待确认） |
| 7 | 已关闭 | 未支付被取消/超时 | — |
| 8 | 已退款 | 金额已退回用户余额 | — |

**资金流向**：下单支付 → 从用户余额扣除（平台托管）→ 订单完成 → 按 `platform_fee_rate` 抽成，其余进陪玩余额 → 陪玩申请提现（冻结）→ 后台打款（扣冻结、累计提现增加）。

- 提现默认是「线下打款 + 后台审核」，平台拿到用户收款账号后人工转账并在后台点「已打款」，也可导出打款清单 CSV

## 十三、验证方式配置（邮箱验证码 / 手机短信验证码）

后台可以**分别**为「注册」和「找回密码」选择验证方式：`关闭` / `邮箱验证码` / `手机短信验证码`（平台设置 → 验证方式）。渠道没配置完整时会自动按「关闭」处理，避免用户卡在收不到码的页面。

### 邮箱验证码（SMTP）
后台「平台设置 → 邮箱 / SMTP」填写：
   - **SMTP 服务器**：`smtp.qq.com`、`smtp.163.com`、`smtp.exmail.qq.com` 等
   - **SMTP 端口**：SSL 用 `465`，STARTTLS 用 `587`
   - **SMTP 加密方式**：`ssl` / `tls` / `none`
   - **SMTP 账号**：你的邮箱地址
   - **SMTP 密码 / 授权码**：QQ、163 邮箱必须填「**授权码**」（在邮箱设置里开启 SMTP 服务后生成），填登录密码会认证失败
   - **发件人邮箱 / 名称**：留空则使用 SMTP 账号与站点名称
2. 保存后点「**发送测试邮件**」验证配置（收不到先看垃圾箱）。
3. 到「验证方式」里把「注册验证方式」「找回密码验证方式」选成 **邮箱验证码**。

### 手机短信验证码（阿里云）
后台「平台设置 → 短信（阿里云）」填写：**AccessKeyId / AccessKeySecret / 短信签名 / 模板 CODE**（模板内容必须包含 `${code}`），区域默认 `cn-hangzhou`；保存后可用「发送测试短信」验证，然后在「验证方式」里把对应环节选成 **手机短信验证码**。

> 想接其他短信服务商（腾讯云、容联云等），在 `app/Sms.php` 的 `sendCode()` 里加一个 driver 分支即可，其余逻辑（验证码生成、防刷、校验）都已统一在 `app/VerifyCode.php`。

> 只有 SMTP 配置完整时，开关才会真正生效；否则注册/找回密码不会要求邮箱验证，后台会显示黄色提示。

### 行为说明
- 验证码 6 位数字，**10 分钟有效**，校验成功后立即作废；单个验证码最多尝试 5 次。
- 防刷：同一目标同一场景 **60 秒内只能发 1 次**、每天最多 5 次；**同一 IP 每天最多 20 条**；页面上发送按钮自带 60 秒倒计时。
- 验证码统一存在 `verify_codes` 表（`target` + `channel` + `scene`），邮箱与短信共用一套生成/校验/防刷逻辑。
- 注册：按所选渠道要求填写邮箱或手机号并输入验证码；关闭验证时两者选填，但仍做格式与唯一性校验。
- 找回密码：登录页「忘记密码」→ 填邮箱或手机号 + 验证码 + 新密码；关闭该功能时提示联系客服。

### 邮件文案（注册 / 找回密码各一套）
两封邮件口吻不同，正文全部居中、验证码大字突出：

- **注册**：标题「听说您想加入我们」→「这是我们之间的秘密」→ 验证码 →「打死不要告诉任何人 · 请在 N 分钟内使用」
- **找回密码**：标题「听说您遇到一些麻烦，没关系的」→「这是您的密钥，我刚刚拿到的，趁热」→ 验证码 →「超过 N 分钟就凉了，请尽快使用」

其中 **N 取自后台「平台设置 → 验证方式 → 验证码有效期(分钟)」**（默认 3 分钟），所以文案里的时长永远和真实有效期一致。改文案在 `app/VerifyCode.php` 的 `mailTemplate()`。
- 邮箱可在「个人中心」修改（唯一性校验）；建议引导用户填常用邮箱，否则无法自助找回密码。
- 相关表：`users.email`（新字段）、`email_codes`（新表，第 14 张）；旧库升级只需重新访问一次 `install.php`，`SchemaSync` 会自动建表补字段。

### 手机端适配
前台与后台都做了窄屏适配：**表格在卡片内横向滑动**（列不再被压扁成一团）、筛选栏与表单自动纵向堆叠并撑满宽度、订单卡片在窄屏换行显示、后台侧边栏在手机上变成**可左右滑动的导航条**、超小屏（≤420px）进一步压缩留白。

**底部 Tab 导航**：手机上固定在底部，内部容器 `max-width: 560px` 居中、每个 Tab `flex: 1 1 0` 均匀分布；桌面端（≥701px）变成底部居中的**悬浮胶囊条**（宽 520px、圆角、投影），不再铺满整行。图标使用内联线性 SVG（当前色描边），选中态为品牌色加粗，未选中为灰色，点击有浅色反馈。「我的」页九宫格同样是彩色圆角图标块。

> **改了 CSS 没生效？** `asset()` 会自动给 `style.css` / `admin.css` / `app.js` 加上 `?v=文件修改时间`，上传新文件后浏览器会自动拉取新版本，不需要手动清缓存（首次仍建议按一次 Ctrl+F5）。
