# 发版指南（每次发布新版本 App 时看这一份）

> **一句话规则**：改动代码后，**必须同时做两件事** —— ① 改 `build.gradle.kts` 里的 `versionName`，② 在后台填「App 最新版本号」。少做任何一件，更新弹窗都会出问题。

---

## 一、更新弹窗是怎么工作的

```
App 启动
   ↓
读自己的版本号（build.gradle.kts 里的 versionName）
   ↓
请求服务端 common/init，拿到后台填的「App 最新版本号」
   ↓
比较：后台版本 > 本机版本 ？
   ├─ 是 → 弹更新窗（可强制、可关、可点「立即更新」跳下载地址）
   └─ 否 → 不弹
```

**版本比较是「按点拆分、逐段比数字」**，不是字符串比较 ——
所以 `1.10` **大于** `1.9` 是对的（字符串比较会判反，这是个常见坑）。
`1.1` 和 `1.1.0` 视为相同。

---

## 二、发新版必须做的两件事

### ① 改 App 版本号

**文件**：`xuyuan/app/build.gradle.kts`

```kotlin
defaultConfig {
    ...
    versionCode = 2          // ← 每次 +1（给安卓系统比大小的整数）
    versionName = "1.1"      // ← 每次往上涨（App 报给服务端的版本）
}
```

| 字段 | 规则 | 忘了会怎样 |
|---|---|---|
| `versionName` | 每次发布往上涨（1.0 → 1.1 → 1.2） | **更新弹窗永远弹**：App 一直报旧版本，服务端版本比它大 |
| `versionCode` | 每次发布 +1 | 安卓可能**拒绝覆盖安装**（新包 versionCode 必须大于已装的） |

> ⚠️ **这是最容易犯的错**：改完功能直接打包，忘了动这两行。
> 结果就是你更新了十几次，App 每次启动都还在说「我是 1.0」。

### ② 在后台填最新版本号

**位置**：后台 →「平台设置 → 运营展示」

| 字段 | 填什么 |
|---|---|
| **App 最新版本号** | 填本次发布的版本，例如 `1.1` |
| **强制更新** | 勾上 → 弹窗关不掉，用户必须去更新 |
| **App 下载地址** | 新 APK 的下载链接（见下面第三节） |
| **App 更新说明** | 弹窗里显示的更新内容，**用户可一键复制** |

## 三、对照表：谁能看到弹窗

假设你发布 **1.1**（App 里 `versionName = "1.1"`，后台填 `1.1`）：

| 用户手上 | 后台填 | 比较 | 结果 |
|---|---|---|---|
| 1.0（旧版） | 1.1 | `1.1 > 1.0` | ✅ 弹窗（正常） |
| 1.1（新版） | 1.1 | `1.1 > 1.1` | ✅ 不弹（正确） |
| 1.1（新版） | 1.2 | `1.2 > 1.1` | 弹窗（该发 1.2 了） |

**核心要求**：`后台的版本号` 要**始终等于最新发布的那个版本**，而 `App 的 versionName` 每次发版都要跟上。

## 四、完整发版流程（按顺序）

- [ ] **1. 改 `build.gradle.kts`**：`versionName` +0.1、`versionCode` +1
- [ ] **2. 打包**：Android Studio → `Build → Build APK(s)`
     产物：`xuyuan/app/build/outputs/apk/debug/app-debug.apk`
- [ ] **3. 把 APK 传到能公网访问的地方**（见下方「下载地址怎么给」）
- [ ] **4. 后台填版本信息**：平台设置 → 运营展示 → 版本号 / 下载地址 / 更新说明
- [ ] **5. 自测**：用**旧版**手机打开 App → 应弹窗；点「立即更新」→ 应能下载
- [ ] **6. 用新版装上** → 再打开 → **应不再弹窗**（这一步是验证版本号有没有改对）

### 下载地址怎么给

「App 下载地址」需要是一个**公网能打开的链接**，几种做法：

| 做法 | 说明 |
|---|---|
| **放自己服务器**（推荐） | 把 APK 传到 `public/uploads/app/`，地址填 `http://你的域名/uploads/app/app-1.1.apk` |
| 网盘 / 蓝奏云 | 填分享直链（注意有些网盘会跳转，体验差一些） |
| 应用商店 | 上线后填商店链接 |

> 用自己服务器的话，记得**每次发版换文件名**（带版本号），否则用户可能下到浏览器缓存里的旧包。

## 五、常见问题

**Q：我更新了代码也重新装了，为什么还一直弹更新窗？**
A：**`versionName` 没改**。App 报的还是旧版本号。这是最常见的原因。

**Q：后台填 1.1，App 也是 1.1，还在弹？**
A：检查 `versionName` 是否**真的重新编译进去了** —— 改完 `build.gradle.kts` 必须重新构建，光改文件不打包没用。

**Q：用户点了「立即更新」没反应？**
A：后台「App 下载地址」没填。留空时按钮不显示（弹窗会提示联系客服）。

**Q：想强制所有人升级？**
A：勾上「强制更新」→ 弹窗没有「稍后再说」，按返回键也关不掉。

**Q：更新说明太长会怎样？**
A：弹窗内可滚动，且有「复制更新说明」按钮（用户可以复制到电脑上打开）。

**Q：弹窗什么时候出现？**
A：**App 启动时**（走 `common/init` 握手那一步）。不会每次切页面都弹。

## 六、App 相关配置速查

发版/改配置时最常找的几个位置：

| 想改什么 | 文件 |
|---|---|
| **App 名字**（桌面图标下方文字） | `app/src/main/res/values/strings.xml` → `app_name` |
| **版本号** | `app/build.gradle.kts` → `versionName` / `versionCode` |
| **接口地址**（换服务器） | `app/build.gradle.kts` → `BuildConfig.API_BASE_URL` |
| **http 放行名单**（换服务器） | `app/src/main/res/xml/network_security_config.xml` |
| **最低支持的安卓版本** | `app/build.gradle.kts` → `minSdk`（现在是 26 = 安卓 8.0） |
| **桌面图标** | `app/src/main/res/drawable/ic_launcher_{background,foreground}.xml`（矢量图，改完要重新打包） |
| **站点 Logo**（应用内登录页 / 网页顶部） | **不用改代码** → 后台上传 |

> 换服务器 / 换域名：见同目录的 **MIGRATION.md**（那里有完整清单，App 端要改 2 个文件）。
